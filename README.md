# New Love Plus+ 资源解析工具集（社区版）

> 目标：**不转格式**，直接读游戏原生资源（`.smes` / `.smat` / `.bone` / `.texi` / `.mot` / `.trb`），
> 用它自己的数据渲染角色与动作。
>
> 本仓库同时记录**已确证**与**未解决**的部分，方便社区接手 —— 尤其是 `.mot` 动作格式。

## 二、`.mot` 格式：已经确证的部分

以下每一条都由 **游戏本体 `code.bin` 的反汇编**交叉验证（地址为 VA，`VA = 文件偏移 + 0x100000`）。

### 2.1 容器头（0x20 字节）

```
0x00  'MOT '
0x08  u32  记录数 count
0x0C  u32  【记录→骨骼表的偏移】  (不是文件大小!)
0x10  u32  时长（帧）
0x14  u32  A 池偏移
0x18  u32  B 池偏移
0x1C  u32[count]  每条记录的偏移表
```

### 2.2 记录

```
+0  u16  nk        关键帧数
+2  u16  mask      通道掩码
+4  u16  times[nk] 帧号（严格递增，times[0] == 0）
    对齐到 4 字节
    u32  refs[nk * stride]   指向浮点池
```

- **通道数 `nch` = `popcount(mask & 0x1FF)`**（逐位 `tst #0x100` … `tst #0x1`，见 0x00740A80–0x00740AC4）
- **`refs` 的 bit31 选池**：置位 → B 池，否则 A 池（0x00740CA0）
- **每个关键帧占 `stride` 个浮点**，`stride = 2 × nch`（见 2.5，**这是本仓库最重要的修正**）

### 2.3 通道位 → 分量

游戏的分发器 `0x0069B26C` 逐位处理并写入一个 9 槽结构：

```
位 8 → +0x00   位 7 → +0x04   位 6 → +0x08      ← 一组（平移）
位 5 → +0x18   位 4 → +0x1c   位 3 → +0x20      ← 一组（旋转）
位 2 → +0x0c   位 1 → +0x10   位 0 → +0x14      ← 一组（缩放）
```

**旋转组 = 位 5/4/3 由三处独立确认：**
1. 分发器的写入点（上表）
2. 求值循环 `0x002227C4` 把 `sp+0x18` 传给 `0x0069B904`（三角度 → 旋转矩阵）
3. 结构布局（采样器 `vstmia sp, {s0..s7}` 写 0x00..0x1c）

### 2.4 插值

**线性**：`value = A + k * (B − A)`，**没有切线**
- 实现：`0x00740C9C`（`vsub` + `vmla`）
- 键帧区间：线性扫描 `[idx, idx+1]`（`0x00740B44`）

### 2.5 ★ 关键帧步长 = `2 × nch`（本仓库最重要的修正）

**曾长期误判为 `nch`，症状是「六根不同腿骨带同一个 ~80.9 值」和「角色永久蹲姿」。**

原始池数据（`m_00010_40.mot` 记录 1，`mask=0x0038`，`nch=3`，`nk=61`）：

```
refs 是完美连续的池下标：0x19E, 0x19F, 0x1A0, 0x1A1, …, 0x1B5

按 stride=3 读通道 0：
   [-4.394, 80.811, -2.875, -0.045, 0.121, -0.002, -4.881, 80.785, …]   ← 每隔一个跳到 80.8
按 stride=6 读通道 0：
   [-4.394, -2.875,  0.121, -4.881, -2.817,  0.116, -5.347, -2.760, …]   ← 平滑 ✓
```

**⇒ 每个关键帧实际占 `2 × nch` 个浮点。用 `nch` 读取等于「每隔一个取一个」，
把两组量交错混在一起。**

**修正后的变化：腿部不再呈现膝弯约 80° 的蹲姿，身高在多帧之间更稳定。**

> ⚠️ **注意：这只说明「数据在时间轴上变平滑了」，不等于「姿势与游戏一致」。**
> 步长 2×nch 的结论来自数据自身（值的平滑性），是可靠的；
> 但「渲染出来的姿势是否正确」从未与游戏内画面对照过。

### 2.6 记录 → 骨骼：文件内的显式表

`header + 0x0C` 指向 `u32[count]` 数组，每条记录一个骨骼号：

```
m_hand000.mot     [274, 275, …, 288]        → 减 225 → [49, 50, …, 63]
m_lower011.mot    [303, 304, …, 321]        → 减 225 → [78, 79, …, 96]
m_00010_40.mot    [12, 13, 14, 15, 123, …]  → 不变（< 225）
```

**编码：`值 = 骨骼号 + 225 × bank`**（bank ∈ {0,1}）

**为什么是 225 而不是 256：** 256 对身体动作结构上更整齐，但 225 让 `m_hand000`
精确落在**骨骼 49~63** —— 而这正是 `m_hand` 模型蒙皮用的那 15 根连续手骨。

### 2.7 ★ 未解决：骨骼语义

**以下是本仓库最需要社区帮忙的部分。**

`code.bin` 里给出了格式，但**骨骼索引空间**仍有矛盾：

| 现象 | 数据 |
|---|---|
| 骨架链（已实测） | 左臂 `49←42←33←30←22←21←20←5`；右臂 `210←203←194←191←24←21←20←5` |
| 脊柱/颈部 | 骨骼 `20 / 21 / 22 / 24` |
| 绑定姿势 | **所有骨骼旋转为 `(0,0,0)`**；手臂水平（T-pose），由平移定义 |
| 手臂网格绑定 | `30, 33, 42, 191, 194, 203, 210~224` |
| 但绝大多数动作驱动 | `12~43`（腿）、`123~155`、`206~210` —— **与手臂网格几乎不重合** |
| 结果 | **手臂保持在 T-pose，不随动作改变** |
| 分层动作 | `m_handNNN`（8 个）、`m_lowerNNN`（19 个）、`m_skirt_NNN`（13 个）、`m_upperNNN`（15 个）—— 只有 `m_handNNN` 的目标骨骼已确认（49~63 ✓） |
| 尝试过但失败的组合 | 15 个 `upper` 层全部（都会把手臂折成平板或让头脱离）；3 个驱动完整手臂骨骼的 `_10` 动作；记录↔骨骼配对整体偏移扫描（60 种）；绝对/相对旋转语义；轴排列 6 种 |

**具体疑问：**
1. 手臂网格绑定的 `191/194/203/210~224` 由**谁**驱动？全库只有 3 个 `_10` 动作覆盖它们，且套用后角色形变。
2. `m_lowerNNN` / `m_skirt_NNN` 实际驱动**头发/面部骨骼（78~96）**，那么它们在游戏里的正确用法是什么？
3. 是否存在**运行时基础姿势**（手臂自然下垂）？绑定姿势是 T-pose，而所有"平静"动作的手臂幅度只有 ~18°，不足以把手放下来。
4. `code.bin` 里**没有 `.mot` 字符串**（`'.mot'` 命中 0），说明动作文件名不是代码拼的 ⇒ **身体动作与分层变体的配对规则在数据里**（577 个 `.dbin2` 脚本里也未找到明文动作名）。**这个配对规则是解开手臂问题的关键。**

## 四、怎么用

### 4.1 安装

```bash
pip install -r requirements.txt      # numpy + Pillow（capstone 只有反汇编脚本需要）
```

**你还需要自备游戏本体的 `img.bin`**（本仓库不含任何游戏数据）。

### 4.2 跑起来（30 秒）

```bash
python quickstart.py --img /path/to/img.bin --out frame.png
```

输出：

```
[1/5] 读取模型 ...      38 个部件, 254 根骨骼
[2/5] 计算绑定姿势 ...
[3/5] 采样动作 ...      （未指定动作时渲染绑定姿势）
[4/5] 蒙皮 ...
[5/5] 渲染 ...          -> frame.png
```

**带动作和背景：**

```bash
python quickstart.py --img img.bin --motion m_00010_40.mot --time 20 \
                     --bg bs_0000_00_00.jpg --yaw 30 --out step.png
```

| 参数 | 说明 |
|---|---|
| `--img` | 游戏本体 `img.bin`（必需） |
| `--motion` | 动作名，如 `m_00010_40.mot`；省略则渲染绑定姿势 |
| `--time` | 帧号 |
| `--bg` | 背景名，如 `bs_0000_00_00.jpg` |
| `--yaw` | 相机水平角（度） |
| `--size` | 输出尺寸，默认 `600x860` |

`quickstart.py` 只有 5 步、约 150 行，**是理解整条链路的入口**：

```
读模型 → 绑定姿势（相机按它取景一次，全程固定）→ 采样动作 → 蒙皮 → 渲染
```

### 4.3 目录结构

```
quickstart.py           ★ 从这开始：最小可跑示例
requirements.txt

native/                 ── 核心库 + 常用工具 ──
  nlp_pack.py           容器读取（img.bin / PACK / SERI）
  nlp_model.py          模型 / 骨骼 / 材质
  nlp_tex.py            纹理解码（5 种格式）
  nlp_mot.py            ★ .mot 解析与采样（步长、通道、骨骼表、插值）
  nlp_render.py         软件光栅器（固定相机、蒙皮、背景合成）
  nlp_bg.py             背景加载
  compose.py            角色装配 + 图层定义

  sweep_body.py         ★ 多帧扫描 → 接触表（最可靠的验证工具）
  anim.py               动画 → PNG + GIF
  motion_sheet.py       多个动作并排对比
  showcase.py           带背景的成品渲染

diagnostics/            ── 一次性排查脚本（证据链，不是使用入口）──
  dis_arm.py            ARM 反汇编辅助（VA ↔ 偏移、常量搜索）
  bone_owner.py         骨骼 → 网格归属实测
  arm_bones.py          手臂顶点绑定哪些骨骼
  layer_overlap.py      图层之间的骨骼争用
  upper_sweep.py        15 个 upper 层评分
  region_motion.py      分部位位移
  table_validate.py     记录 → 骨骼表验证
  shift_scan.py         记录↔骨骼配对偏移扫描
  absolute_layers.py    分层动作绝对/相对语义对照
```

> `diagnostics/` 里的脚本记录了每个结论是**怎么被证伪或证实的**。
> 如果你要接手骨骼语义问题，读这些比读格式说明更有用 —— 它们包含我走过的弯路。

### 4.4 常用命令

```bash
# 多帧扫描一个动作（最可靠的验证方式）
LP_SWEEP_MOTION=m_00010_40.mot python native/sweep_body.py

# 动画 GIF
LP_ANIM_MOTION=m_00010_40.mot LP_ANIM_FRAMES=48 python native/anim.py

# 多个动作并排
python native/motion_sheet.py
```

### 4.5 作为库使用

```python
import sys; sys.path.insert(0, 'native')
import nlp_pack as N, nlp_model as M, nlp_mot as MOT, nlp_render as R

model = M.load_model('img.bin', 'm_01_012')     # 服装
objs, bones = ..., model.bones

MOT.BIND_ROT = {b.index: tuple(b.rotation) for b in bones}
mot  = MOT.load_mot_final(raw_bytes, 'm_00010_40.mot')
pose = MOT.sample_present(mot, t)               # {bone: {'T': {...}, 'R': {...}}}
# 之后见 quickstart.py 第 4~5 步
```

## 五、给社区的话

**已经能做的：** 读出角色、骨骼、材质、贴图、背景，用游戏原生数据渲染出角色；
动作能读、能插值、能渲染。

**⚠️ 但请注意：本仓库不声称「渲染正确」。** 姿势绑定与腿部动作**均为未验证状态** ——
它们只是「能跑通」，没有与游戏内实际画面对照过。不要把它们当作已解决的问题。

**卡住的地方：** `.mot` 的**骨骼语义**。格式本身（容器、记录、通道位、池、插值、步长、
记录→骨骼表）都已由游戏代码确证，但：

- 手臂网格绑定的骨骼段（`191~224`）几乎不被任何动作驱动
- 分层动作（`lower` / `skirt`）驱动的是头发骨骼
- 找不到「手臂自然下垂」的基础姿势
- **身体动作 ↔ 分层变体的配对规则不在 `code.bin`，也不在 `.dbin2` 明文里**

**如果你解过这个游戏的动画系统，或者知道动作配对的规则，欢迎开 issue。**
