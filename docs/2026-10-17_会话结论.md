从"待机动作不对"一路追到"颜色为什么不像实机"。**下面每一条都是被用户指出错误后实测推翻/修正过的**，

## 1. 动作：一个"待机"是**四个文件**串成的闭环

待机**不是**单个 `.mot` 循环 ✗ —— 而是：

```
m_XXXXX_40 (过渡) → m_XXXXX_41 (保持) → m_XXXXX_42 (过渡·反方向) → m_XXXXX_43 (保持) → 回到 _40
```

`m_00010` 实测四处衔接像素差 **0.02 / 0.02 / 0.07 / 0.02**，而循环内部帧间差均值 **1.51**
⇒ 串起来播放**完全无缝** ✓ 全库 37 组里 **31 组**符合这个结构 ✓（四处衔接最大 0.08）。

**教训**：动作的"循环单位"不一定是单个文件 ✗。先看相邻编号再下结论 ✓。

---

## 2. 材质是**多贴图**的（眼睛"少一层"的根因）

`.smat` 的一个材质可以有多个 texture unit ✓，我们以前只渲染 unit0 ✗：

```
m_eye      = m_eye + m_eye_uru(水润) + m_eye_light(高光)   三层 ✓
m_face_01  = 脸 + m_cheek_col(腮红)
m_face_col = 阴影 + m_face_02(眉毛)
```

**合成规则**（实测定的）：
- **黑底亮点**层（高光/反光）→ **加法** ✓
- **整片色**层（腮红）→ **相乘，但必须乘该层自己的 alpha** ✓（否则整张脸染红 ✗）
- **高光层的 R/G/B 是同一处高光的三个动画帧** ✓ → **每帧只取一个通道** ✓✓
  （用 max 合并会出现"三个点" ✗ —— 用户一眼看出来的 ✓）

---

## 3. 贴图格式：声明可能写错，**用数据量反推**

`m_face_col` 声明 LA4（1 字节/像素）✗，实际数据量对应 **2 字节/像素** ✓（rgba5551）。

```
TEX 数据量 = w × h × 每像素字节 × 1.25（带一级 mipmap）
与声明矛盾时，以【数据量】为准 ✓
```

不改的话：只读到一半数据 → 解出一张**噪点图** ✗。

---

## 4. 这是**三渲二**：贴图是画好的，别再加光照

证据：SMAT 里有 LUT toon ramp ✓、贴图里烘焙了明暗（围裙"上白下灰蓝"）✓、多贴图叠加 ✓、**没有黑描边** ✗。

⇒ **衣服 / 围裙必须 unlit** ✗（`LP_UNLIT='_bo,_wa'`）✓ ——
加光照会把贴图里的渐变压平，围裙永远是"淡蓝一片" ✗ 而不是"白" ✓。

**但皮肤/头发要受光** ✓（全身 unlit 会发白发平 ✗）。

---

## 5. 自动拟合增益不可靠 ✗ —— 改用"实测反算"

`tools/fit_gain.py` 按**材质 ID 掩膜**取中位数拟合 ✓，但它选中的**屏幕区域经常不对** ✗：
- 脖子 `m_01_005_ne` → 取样落在领口白色处 ✗
- 脸 `m_face` → 报 Δ=0 但实测偏暗 40+ ✗

**正确做法** ✓：**指定部位 → 实测中位色 → 反算增益** ✓。
例：脸实测 (227,162,136) → 目标 (254,203,174) → 增益 ×(1.119,1.253,1.279) → 实测 (254,202,174) ✓✓

**耦合** ✓：`m_face` 和 `m_01_005_ne` 是**独立**增益 ✓ —— 改肤色必须**同比例**改脖子 ✓，否则立刻出现色带 ✗。

## 5.5 ★★★ 最大的一个 bug：material_gain 的 NameError（已修 ✓）

**现象**：颜色增益配了不生效 ✗ —— 拟合永远发散 ✓、裙子怎么调都不变 ✓、头发纹丝不动 ✓、
恢复原状失败 ✓。今晚至少 5 次被它坑 ✓。

**根因**（用 LP_DEBUG_GAIN=1 打印抓到的 ✓）：
`
[GAIN] debug failed: name 'material_gain' is not defined
`
material_gain() 定义在 
lp_shade.py ✓，但 lp_render.py 的 unlit 分支里**直接调了它** ✗
→ NameError 被 except 吞掉 → **永远回退成增益 (1,1,1)** ✗✓

**修复**：改成 import nlp_shade as _SS; _SS.material_gain(material)

**效果（立竿见影 ✓）**：
`
修复前：拟合 27 秒 / 10 轮 / 仍发散 ✗（Δ 几十到上百）
修复后：拟合 6.9 秒 / 3 轮 / 收敛 ✓
        蓝裙 Δ=(0,0,-1) ✓   皮肤 Δ=(-1,0,0) ✓   白围裙 Δ=(-1,0,+1) ✓
实机复核（材质 ID 掩膜口径）：蓝裙 (163,225,250) vs 实机 (162,224,249)  Δ=(1,1,1) ✓✓
`

**教训**：except Exception: 用默认值 这种写法会**静默吞掉编程错误** ✗ ——
名字写错和确实取不到值被混为一谈 ✓，而且错了**看不出来**（只是调了没反应）✓。

## 9. ★ 脖子的白圈：最漂亮的一次诊断（2026-10-17 收尾）

**用户原话**：「脖子中间那块区域是白的，但是下面却是好的，这是什么原理？」

**推理链（全靠这一句）** ✓：
```
"只有中间白、下面好" ⇒ 不可能是打光 ✗（打光会连续过渡）
                     ⇒ 一定是一个【独立的小零件】盖在中间 ✗
⇒ 用材质 ID 掩膜一扫：果然是 m_01_005_ne
⇒ 它是一圈【领口内衬】，游戏里被外层领口挡住 ✓，我们没做遮挡 ⇒ 露出来 ✗
⇒ 隐藏它：6 套衣服全部正常 ✓✓（连高领毛衣的领子都还在 ✓）
```

**这比我当晚做的所有"调参数"都有效** ✓ —— 我一直在调打光/增益/对比度 ✗，
而正确答案是**根本没做遮挡** ✗。教训：**"只有某一块不对"优先怀疑是独立零件/层级问题** ✓，
而不是先去调渲染参数 ✓。
