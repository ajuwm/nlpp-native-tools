## 3. 灯环境 entry（0x50 字节）字段含义（由 0x1138CC 反汇编确认）

对第 i 盏灯，`env = ctx+0x1018+i*0x50`：

| env 偏移 | 作用 |
|---|---|
| `+0x00..0x0C` | **ambient 通道系数** (4 float) |
| `+0x10..0x1C` | **diffuse 通道系数** |
| `+0x20..0x2C` | **specular 通道系数** |
| `+0x30..0x3C` | **光方向/位置**（世界空间向量，经矩阵变换） |
| `+0x40..0x4C` | 聚光灯方向 |

对应 `0x1138CC` 的公式（`obj` = 场景灯光对象，`env` 如上）：

```
Light.DIFFUSE[ch] = int(obj[0x189+ch] * env[0x10+4*ch])
Light.AMBIENT[ch] = int(obj[0x185+ch] * env[0x00+4*ch])
Light.SPEC0[ch]   = int(obj[0x18D+ch] * env[0x20+4*ch])
Light.SPEC1[ch]   = int(obj[0x191+ch] * env[0x20+4*ch])
Light.DIRECTION   = M(ctx+0x104) * env[0x30]   （再转 1.15 定点）
全局 ambient[rgb] = clamp( paletteA[rgb] + int(paletteB[rgb] * ctx[0x1000+4*ch]) )
```

> 注意 obj 调色板在代码里是**反序读取**（R 用 +0x183/+0x187，G 用 +0x182/+0x186，
> B 用 +0x181/+0x185），换算时按上表；本文脚本已处理。

## 5. 交叉验证：找到了游戏自己写的 GX 命令块

在 `ctx+0xF38` 指向的帧数据区（`0x8704510`）里，扫描到真实的 PICA200 命令流：

```
0x87049D0: 18 04 00 80      → 0x80000418   (LIGHTING_CONFIG0 参数)
0x87049D4: c3 01 0f 00      → 0x000F01C3   header: reg=0x1C3 mask=0xF
0x87049D8: 00 00 77 00      → 0x00770000    (LIGHTING_CONFIG1)
0x87049DC: c4 01 04 00      → 0x000F01C4   header
0x87049E0: 00 03 00 00      → 0x00000300    (LUT_INDEX)
0x87049E4: c5 01 0f 00      → 0x000F01C5   header
0x87049E8: 3d 02 00 00      → 0x0000023D    (LUT_DATA #0)
0x87049EC: c8 01 ff 07      → 0x07FF01C8   header: 128 words LUT_DATA
0x87049F0..: 128 个 LUT 数据（与旧 DUMP 的 LUT 数据同源）
```

- `LIGHTING_CONFIG0 = 0x80000418`、`CONFIG1 = 0x00770000`
  **与旧月 DUMP 数据完全一致** ⇒ 配置常量被确认。
- 说明 `docs/03` 的 GX 命令格式（参数在前、header 在后、header 位域）是对的。

## 6. 还没拿到的

1. **雾参数**：主菜单 `ctx+0xE40` 区全 0（无雾）；需要在有雾的场景（约会/剧情）再抓一次。
2. **其它场景的光照预设**：主菜单只代表菜单；故事模式的场景会用不同对象/灯光。
   方法已通：进入对应画面后再跑 `live_lights.py <tag>` 即可。
3. `0x1275C0` 的逐灯命令打包细节（颜色 10/10/10 的精确位序）——颜色字节已确定，
   只差最终打包形式（可再读 GX 命令块确认）。
