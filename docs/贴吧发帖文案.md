## 正文

```
先说结论：

【已经对的】New Love Plus+（日版 00040000000F4E00）的模型、骨骼、材质、贴图、
背景、相机，全部能用游戏自己的格式读出来并正确渲染 —— 我出了高分辨率的绑定姿势图
逐项核对过：双腿完整伸直、双脚落地、裙子格纹无接缝错位、面部五官位置全对、
比例自然。这一整条链是通的。

【还没对的】动作文件 .mot 能读、能插值、能出画面，但**姿势不对** ——
套上动作后角色会悬空、双腿蜷曲、手臂僵在 T-pose。

格式本身我已经用游戏 code.bin 反汇编确证了大半，卡住的是最后一层"骨骼语义"：
这些骨骼编号对应身体哪个部位、谁驱动谁。想请懂的人一起看看。

■ 仓库
https://github.com/ajuwm/nlpp-native-tools

只含解析器和渲染器，不含任何游戏资源，需要自备本体。

■ 已经能做到什么

· 读 romfs/img.bin（PACK/SERI 容器），按文件名取资源
· 模型 .smes：顶点/法线/UV/骨骼权重/索引
· 骨骼 .bone：254 根共享骨架，父子关系 + 绑定变换
· 材质 .smat / 纹理 .texi：5 种纹理格式，137 处逐字节验证过
· 背景 bs_*.jpg：1356 张，512×672
· 相机 cam_ang_*.cdb：70 字节 = 35 个 u16，eye/target/fov 都解出来了
· 动作 .mot：容器、记录、通道、插值、骨骼表都能读，能渲染出连续动作

全程不转成 OBJ/glTF，直接用游戏自己的数据渲染。

■ .mot 格式已经确证的部分

这块是拿游戏本体的 code.bin 反汇编对着解的（明文 ARM，8,126,464 字节，
VA = 文件偏移 + 0x100000），所以每条结论都能给出地址：

  0x00740A68   ldrh  nk         记录的关键帧数
  0x00740A78   ldrh  mask       通道掩码
  0x00740A80   tst #0x100...   通道数 = popcount(mask & 0x1FF)
  0x00740C9C   vsub + vmla     线性插值（没有切线）
  0x00740CA0                   refs 的 bit31 选池
  0x0069B26C   tst #0x100...   位 → 槽的完整分配
  0x0069B904   常量 256/2π      三角度 → 旋转矩阵
  0x00740D08                  骨骼查询 obj->[8]->[0x0C][记录号]

文件头：
  0x00 'MOT '
  0x08 记录数
  0x0C 【记录→骨骼表的偏移】（不是文件大小）
  0x10 时长
  0x14 A池  0x18 B池  0x1C 记录偏移表

每个关键帧占 2×nch 个浮点（nch = 掩码置位数）—— 这一条踩了很久的坑，
一开始按 nch 读，等于每隔一个取一个，把两组量交错混在一起，
表现出来就是"六根不同腿骨都带同一个 80.9 值"和"角色永远蹲着"。

记录→骨骼： header+0x0C 指向一张 u32 表，值 = 骨骼号 + 225 × bank。
  为什么是 225 不是 256：256 对身体动作结构上更整齐，但 225 才能让
  m_hand000 精确落在手骨 49~63 上，而那正是 m_hand 模型蒙皮用的 15 根连续手骨。

■ 卡住的地方（想请教）

1. 手臂不动。手臂网格绑定的是骨骼 30/33/42/191/194/203/210~224，
   但绝大多数动作只驱动 12~43 和 123~210，两段几乎不重合。
   全库只有 3 个 _10 后缀的动作覆盖完整手臂骨骼，套上去角色会形变。

2. 分层动作对不上。m_handNNN 的目标骨骼已确认（49~63，手），
   但 m_lowerNNN / m_skirt_NNN 驱动的其实是【头发骨骼 78~96】，不是下半身。
   这几个层在游戏里的正确用法是什么？

3. 找不到"手臂自然下垂"的基础姿势。绑定姿势是 T-pose，而所有"平静"动作的
   手臂幅度只有 ~18°，不足以把手放下来。是不是有运行时基础姿势？

4. 最关键的一条：身体动作和分层变体的【配对规则】。
   code.bin 里搜 '.mot' 命中 0，577 个 .dbin2 脚本里也没有明文动作名，
   说明配对规则在某个数据表里。找到它应该就能解开手臂。

■ 试过但失败的方向（省得重复劳动）

· 15 个 m_upperNNN 层全试过，都会把手臂折成平板或让头脱离
· 3 个驱动完整手臂骨骼的 _10 动作，套用后角色形变
· 记录↔骨骼配对整体偏移扫描（60 种）
· 绝对/相对旋转语义对照
· 6 种轴排列全扫
· bank 0/1 消融
· 分层动作旋转改成绝对语义

这些也写在仓库的 docs/JOURNEY.md 里了，连"我犯过哪些错"都记着——
比如用记录长度吻合去推断步长（间接判据），而没用"值在时间轴上是否平滑"
（直接判据），结果绕了几十轮。diagnostics/ 目录里的脚本就是这些排查过程。

■ 怎么用

pip install -r requirements.txt
python quickstart.py --img /path/to/img.bin --out frame.png

带动作和背景：
python quickstart.py --img img.bin --motion m_00010_40.mot --time 20
                     --bg bs_0000_00_00.jpg --yaw 30 --out step.png

■ 说明

仓库只含解析器与渲染器，不含任何游戏资源，请自备本体，勿分发游戏数据。
README 里也如实标了：姿势绑定和腿部动作【能跑通但未与游戏内画面对照过】，
所以不写"正确"。格式部分才是真正确证的。

有懂这个游戏动画系统、或者知道动作配对规则的，欢迎来仓库开 issue。
```

## 发帖提示

1. **标题带【工具】或【分享】比【求助】更容易被点开**，但如果你想让人帮忙，用【求助】也合理
2. **正文第一段就把结论说清楚** —— 贴吧读者大多只看前三行
3. **仓库链接单独占一行**，方便直接点
4. **如果被删帖**，通常是关键词触发，可以试着把"解包"改成"资源解析"、把游戏名写成"NLPP"
5. **有人问"能不能汉化"** —— 说明那是另一条线，本仓库只管解包
6. **注意不要贴游戏资源或截图里出现游戏画面**，容易引版权问题（仓库里也刻意不含资源）
