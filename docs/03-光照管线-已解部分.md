# 03 · 光照管线：已解出的部分

> 本文件记录**证据已确认**的结论，以及尚未解决的缺口。所有地址都是 `VA = 文件偏移 + 0x100000`。
> 工具：`scripts/armdis.py`、`scripts/armref.py`、`scripts/scan_lights.py`。

---

## 1. 先决知识：3DS PICA200 命令格式（3dbrew 确认）

每个 GPU 命令 = **[参数 word(s)] + [header word]**（参数在前、头在后！）：

```
header:  bits 0-15   = 寄存器 ID
         bits 16-19  = 参数 mask（0xF = 4 字节全写）
         bits 20-27  = extra 参数个数（0 = 只有 1 个参数 word）
         bit  31     = 连续写模式（连续写下一个寄存器）
```

> 这一条推翻了我最初"header 在前"的直觉。用 DUMP 数据验证时也是同一结论（`nlpp-native-tools/docs/2026-10-18_光照重构.md`）。

### Fragment lighting 寄存器（0x140–0x1D2，按 3dbrew）

| 组 | 寄存器 | 说明 |
|---|---|---|
| LIGHTi (i=0..7) | `0x140+0x10i` SPECULAR0 / `+1` SPECULAR1 / `+2` DIFFUSE / `+3` AMBIENT / `+4` XY / `+5` Z / `+6` SPOTDIR_XY / `+7` SPOTDIR_Z / `+9` CONFIG / `+0xA` ATTENUATION_BIAS / `+0xB` ATTENUATION_SCALE | 每盏灯 12 个寄存器 |
| 全局 | `0x1C0` LIGHTING_AMBIENT / `0x1C2` NUM_LIGHTS / `0x1C3` CONFIG0 / `0x1C4` CONFIG1 / `0x1C5` LUT_INDEX / `0x1C6` ENABLE1 / `0x1C8..` LUT_DATA / `0x1D0` LUTINPUT_ABS / `0x1D1` LUTINPUT_SELECT / `0x1D2` LUTINPUT_SCALE | — |
| 雾 | `0xE0` TEXENV_UPDATE_BUFFER / `0xE1` FOG_COLOR / `0xE6` FOG_LUT_INDEX / `0xE8..` FOG_LUT_DATA | — |

## 2. 已定位的代码

### 2.1 全局灯光命令构造：`0x121174`（函数 A）

- 入参：`r0` = "lighting context" 结构体，`r1` = GPU 命令缓冲写指针，`r2` = 标志（0/1）。
- 功能（逐条确认）：
  1. 用 `r0[0x184..0x18f]` 的一堆 bool 组装 **LIGHTING_CONFIG0** 字（bit16/17/19/20/22/24 等来自这些字节）；
  2. 写 `LIGHTING_AMBIENT`：参数 = `(r0[0]<<20) | (r0[1]<<10) | r0[2]`（**RGB 用 10/10/10 位打包**，字节取自 context 开头 3 字节）；
  3. 写 `LIGHTING_NUM_LIGHTS`：值 = `max(启用灯数 − 1, 0)`（`cmp r4,#0` + `subgt r5,r4,#1` + `movle r5,#0`，`0x1212b8`/`0x1212c0`）；
  4. 循环 8 盏灯，用 `r0[0x164+i]`（启用标志）、`r0[0x16c+i]`、`r0[0x174+i]` 组装 LUTINPUT 位图；
  5. 写 `LUTINPUT_ABS`/`SELECT`/`SCALE`（头在 0x121518–0x121520 的字面池）。
- 引用的 GX 命令头（字面池 0x1213CC–0x1213E0）：

```
0x1213D4  0x000F01C0  → LIGHTING_AMBIENT (mask 0xF, 1 param)
0x1213D8  0x000F01C2  → LIGHTING_NUM_LIGHTS
0x1213DC  0x000F01C3  → LIGHTING_CONFIG0
0x1213E0  0x000F01C6  → LIGHTING_ENABLE1
0x121518  0x000F01D0  → LUTINPUT_ABS
0x12151C  0x000F01D1  → LUTINPUT_SELECT
0x121520  0x000F01D2  → LUTINPUT_SCALE
```

- 反查：`armref.py refs 0x1213D4` → 唯一引用点 `0x121294`。

### 2.2 每盏灯命令构造：`0x1275C0`

- 入参：`r0` = **Light 结构体**（0x2C 字节），`r1` = 命令写指针；返回新的写指针。
- 行为：一次命令写 **LIGHTi 的 12 个连续寄存器**（header = `0x80000000 | ((0x140 + light_index*0x10) | 0xBF0000)`，mask=0xF、extra=0xB 连续写）。
- Light 结构体布局（**实测自本函数读取的偏移**）：

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x00` | u8 | 灯编号 i（0..7）→ 决定寄存器基址 `0x140+0x10i` |
| `+0x01..0x03` | u8×3 | 3 个 bool → 打包进 CONFIG（bit1/2/3） |
| `+0x04..0x06` | u8 RGB | **DIFFUSE 颜色** |
| `+0x07..0x09` | u8 RGB | **AMBIENT 颜色** |
| `+0x0A..0x0C` | u8 RGB | **SPECULAR0 颜色** |
| `+0x0D..0x0F` | u8 RGB | **SPECULAR1 颜色** |
| `+0x10` | u32 | 位置 XY（打包，写 LIGHTi_XY） |
| `+0x14` | u32 | 位置 Z（写 LIGHTi_Z） |
| `+0x18` | u8 | CONFIG 低位（写 LIGHTi_CONFIG） |
| `+0x1C` | u32 | ATTENUATION_BIAS |
| `+0x20` | u32 | ATTENUATION_SCALE |
| `+0x24` | u32 | SPOTDIR_XY |
| `+0x28` | u32 | SPOTDIR_Z |

- 颜色是 **10/10/10 位打包**：`param = (R<<20)|(G<<10)|B`（0x1275D8–0x1275E4 等）。

### 2.3 Light 结构体默认值：构造函数 `0x123848`

```
+0 .. +3   = 0            (编号 / 3 个 bool)
+4 .. +6   = 0xFF 0xFF 0xFF   → DIFFUSE = 白
+7 .. +9   = 0            → AMBIENT = 黑
+0xA..+0xF = 0xFF ×6      → SPECULAR0/1 = 白
+0x10..+0x28 = 0
```

⇒ 默认一盏"白色漫反射 + 白高光 + 黑环境"的灯，位置/方向全 0。

### 2.4 光照 context 初始化：`0x11AAAC`

- 入参 `r0` = 0x190+ 字节的 context（调用方栈上 `sp+0x350` 等）。
- 清空 `r0[0..2]`（ambient RGB）；
- 用**构造函数 0x123848** 构造 8 个 Light（每盏 0x2C），从 `r0+4` 开始排；
- 清空 `r0[0x164/0x16C/0x174/0x17C + i]`（8 组标志数组）与 `0x184..0x1AE`；
- 置 `r0[0x18E]=1`、`r0[0x191]=1`；
- 初始化每盏灯的"编号"字节 `r0[4 + 0x2C*i] = i`。

### 2.5 包装函数：`0x121118`

```
0x121118: r5=r0(context); r4=r2(flag)
          bl 0x1213E4                 ; helper（返回命令写指针 r0）
          r1=r0; r2=r4; r0=r5
          bl 0x121174                 ; 写全局 LIGHTING_* 命令
          for i in 0..7:
            if context[0x164+i]:
              r1=r0                    ; 当前命令指针
              r0=context + 4 + 0x2C*i  ; Light i
              bl 0x1275C0              ; 写 LIGHTi_* 命令
0x121118 结束
```

调用点只有两处：`0x10AA6C`、`0x11FC58`（都在大渲染函数里，context 是栈对象）。

### 2.6 场景/角色光照上下文：`0x1138CC`

- 单调用点：`0x10C68C`。
- 从 `r6`（第二个入参，疑似"角色/模型渲染对象"）读取：
  - `r6[0x181..0x187]` 字节 → 叠加计算后写 `sp[0..2]` = **ambient RGB**（带 clamp 到 0..255 的逻辑）；
  - 全局 `0x009BA094`（BSS 里的渲染上下文）+0x1000 附近的浮点（`vldr s0,[r8,#8]` 等）参与缩放；
  - 调用 `0x11AAAC` 初始化光照 context；
- 说明：**ambient 颜色 = 模型对象上的字节 + 全局光照上下文浮点**，不是硬编码常量。

### 2.7 雾：`0x11ABAC` + 场景函数 `0x113700..0x113820`

- `0x11ABAC` 写 `FOG_LUT_INDEX(0xE6)` + 生成 FOG LUT 数据（VFP 计算，用到常量 4096.0f = `0x45800000`）。
- 唯一调用点 `0x1137A4`，位于函数 `0x1136??..0x113820` 内；该函数还写：
  - `0x000500E0` → TEXENV_UPDATE_BUFFER（mask=5, 额外 1 参数）
  - `0x000F00E1` → FOG_COLOR（4 字节）
- 该函数参数从 `sp[0]/sp[1]` 等读取 → **雾参数来自调用方数据**，不是常量。

### 2.8 全局渲染上下文与接口表

- 全局上下文：`0x009BA094`（BSS；文件里没有初值），由 `0x113840` 初始化。
- 字面池里指向该上下文的引用 77 处，主要集中在 `0x106B5C`–`0x109xxx`（渲染器主体）。
- **图形接口函数表**：`0x106DD8`–`0x106EF0` 是一串函数指针（约 80 项），初始化函数在 `0x106D80` 附近。
  我们已定位的光照/渲染小函数是表项：

```
0x106E20 → 0x10BAF0   （把 6 个 word 写进上下文的灯/参数区 0xEAC 或 0x6C/0x5C）
0x106E48 → 0x10BB68   （绘制/命令派发相关）
0x106EF0 → 0x109600 ...
```

- 这些函数**没有直接 BL 调用点**（`armref`/BL 扫描均为 0）⇒ 通过函数指针（表）调用，
  **说明光照参数是由更高层（engine 命令接口 / 脚本）设置的**。

## 3. 结论（目前能确定什么）

1. **命令格式与寄存器语义**已经完全对上 3dbrew，代码级证据充分。
2. **Light 结构体**（0x2C）与**光照 context**（0x190+）布局已解；默认值已知（白 diffuse/spec、黑 ambient）。
3. **ambient RGB 与雾参数不是硬编码常量**，而是"模型对象字节 + 全局上下文浮点"的组合，
   由函数 `0x1138CC`/`0x1137xx` 在每帧/每次绘制时计算。
4. 全局光照上下文（0x9BA094 + 0x1000 区域）的写入者通过**函数指针表**（0x106DD8 起）间接调用，
   目前没有找到直接调用点 ⇒ 需要解**上层命令接口/脚本系统**才能定位"谁给了具体数值"。

## 5. 2026-11-13 第二轮补充：场景灯光对象（r6）

### 5.1 对象来源

- 绘制函数 `0x10BD30`（大函数，`push {r4-r11,lr}`）里：
  ```
  0x10BD50  ldr r8, [r6, #0xf34]    ← r8 = 全局渲染上下文 0x9BA094 里的"场景灯光对象"
  ...
  0x10C680  bl 0x113644             ← 预处理
  0x10C684  mov r1, r8
  0x10C68C  bl 0x1138CC             ← 场景灯光 setup（r1=r8）
  ```
- 对象的 get/set 接口（函数指针表项，表在 `0x106DD8` 区）：
  ```
  0x10AE94  ldr r2, [r0, #0xf34] / bx lr      get
  0x10AEA8  str r1, [r0, #0xf34] / bx lr      set
  ```
- 图形接口对象初始化函数 `0x106C40..0x106DD8`：把 ~70 个函数指针写进对象偏移 0x40..0x138，
  其中 **`[+0x104] = 0x10BD30`（绘制函数）**、`[+0x100] = 0x10AE94`（get 场景灯光对象）。
  ⇒ 说明引擎用"接口对象"把绘制/场景灯光成套调用；**场景灯光对象的指针就在 ctx+0xF34**。

### 5.2 场景灯光对象里的 6 组 RGB 调色板

`0x1138CC` 从对象读取的字节（**全部是 0..255 的 RGB 颜色**）：

| 对象偏移 | 用途（从写入路径确认） |
|---|---|
| `+0x181..0x183` | 调色板 A 的 RGB（参与算 ambient） |
| `+0x185..0x187` | 调色板 B 的 RGB（与 A 按全局 float 混合算 ambient） |
| `+0x189..0x18B` | → Light0 DIFFUSE RGB（写入 context+4/5/6） |
| `+0x18D..0x18F` | → Light0 AMBIENT RGB（写入 context+7/8/9） |
| `+0x191..0x193` | → Light0 SPECULAR0 RGB（写入 context+0xA/0xB/0xC） |
| `+0x254` | 指针：12 个 float 的光照坐标系/位置数据（`bl 0x120838` 拷贝+归一化） |

写入证据（`0x113A74..0x113BF4`，全是 `ldrb r0,[r6,#0x18x]` → `strb r0,[r4,#n]`，r4=context+4）：

```
r6[0x18B] → [r4+4]    r6[0x18A] → [r4+5]    r6[0x189] → [r4+6]      ← DIFFUSE
r6[0x187] → [r4+7]    r6[0x186] → [r4+8]    r6[0x185] → [r4+9]      ← AMBIENT
r6[0x18F] → [r4+A]    r6[0x18E] → [r4+B]    r6[0x18D] → [r4+C]      ← SPECULAR0
r6[0x193] → [r4+D]    r6[0x192] → [r4+E]    r6[0x191] → [r4+F]      ← SPECULAR1
```

⇒ **角色光照的颜色（diffuse/ambient/specular）来自这个"场景灯光对象"的字节调色板**；
位置/方向来自对象 `+0x254` 指向的 12 个 float（经 `0x120838` 归一化）。

### 5.3 场景灯光 setup 的完整调用顺序（0x1138CC）

```
0x1138CC: r6 = r8(场景灯光对象)
  ... 读 r6[0x210] / 全局 ctx 一致性检查
  0x113914  bl 0x11AAAC          ; 初始化 lighting context（默认 8 盏白灯、黑 ambient）
  0x113918  ambient R = clamp( 混合(r6[0x183], r6[0x187], 全局 float) )
  0x113964  ambient G = ... r6[0x182]/[0x186] ...
  0x1139A4  ambient B = ... r6[0x181]/[0x185] ...
  0x113A10+ 循环 8 盏灯：写 context[0x164+i] 启用标志、context[0x16C/0x174/0x17C] LUTINPUT 位图
  0x113A74+ 把 r6 调色板写进 Light0 的 DIFFUSE/AMBIENT/SPECULAR0/1
  0x113BF8  ldr r0,[r6,#0x254]; bl 0x120838   ; 拷贝 12 个 float（灯光坐标系）到 context
  0x113C08  bl 0x120838 / 0x121BE4            ; 矩阵归一化
  0x113F6C  bl 0x1213E4
  0x113F7C  bl 0x121174                       ; 全局 LIGHTING_* 命令
  0x113F88  bl 0x121524                       ; 8 盏灯的 LIGHTi_* 命令（内部调 0x1275C0）
```

辅助函数：
- `0x121524`：`r0`=context、`r1`=命令指针，循环 8 盏灯调用 `0x1275C0`（与 wrapper 里的循环同款）。
- `0x120838`：拷贝 12 个 float 并用 1.0f 常量做归一化/除法补充（疑似把法线/方向正交化）。
- `0x121BE4`：VFP 矩阵乘法（用于光照坐标系变换）。

### 6. 2026-11-13 第三轮补充：引擎对象 / iface 表 / 光照环境区

### 6.1 引擎对象与 iface 虚表

- 工厂函数 **`0x105A58`**：`bl 0x10EC08`（分配器）→ `r4 = 新对象`；写 `[r4] = vtable`；
  初始化 `r4+0x30..+0x15C`（先用统一 stub `0x107EA8` 填满，再覆盖）；最后
  **`r0 = r4+0x30; bl 0x106B9C`** —— 即在 `engineObj+0x30` 处初始化 **iface 虚表**。
- iface 初始化函数 **`0x106B9C`**：把 ~70 个函数指针写进 iface 对象偏移 `0x10..0x158`。
  关键槽位：

| iface 偏移 | 引擎对象绝对偏移 | 函数 | 语义 |
|---|---|---|---|
| `+0x100` | `+0x130` | `0x10AE94` | **设置场景灯光对象**（见 §6.2） |
| `+0x104` | `+0x134` | `0x10BD30` | **绘制 3D 角色/场景**（用 ctx+0xF34 对象） |
| `+0x78`  | `+0xA8`  | `0x10BAF0` | 写 ctx+0xEAC / ctx+0x6C 的 6 word 参数 |
| `+0x84`  | `+0xB4`  | `0x1094E0` | `ctx+0x7C = arg[4]` |
| `+0x88`  | `+0xB8`  | `0x1094F4` | `ctx+0x80 = arg[4]` |

- 调用方式：`ldr rX, [engineObj, #0x130/0x134/…]; blx rX`（多态调用），所以静态 BL 扫描找不到
  这些函数的调用点 —— 这也是为什么「场景灯光对象从哪来」必须靠**槽位反查**。

### 6.2 场景灯光对象的 setter：`0x10AE94`

```
r0 = 0x9BA094（全局渲染上下文）
r1 = 参数块；新对象指针 = [r1 + 4]
if ([ctx+0xF34] == 新指针) return
[ctx+0xF34] = 新指针        ← 场景灯光对象挂到上下文
[ctx+0x0C] |= 4             ← 置脏标记（该帧需要重算光照命令）
```

⇒ 对象不是 ctx 自己创建的，而是**外部构造后通过 iface 槽 +0x100 传进来**。
下一步只需找「谁填了这个参数块」——即场景/背景加载代码。

### 6.3 全局上下文 0x9BA094 的光照环境区（0x1000 起）

初始化函数 **`0x109380`**（`push {r4-r7,lr}`）实测：

```
ctx+0xFF8 / ctx+0xFFC  = 0
ctx+0x1000..0x1014     = 0（5 个 float）
for i in 0..7:                                  ; 8 盏灯的"光照环境"结构，每个 0x50 字节
    p = ctx + 0x1018 + i*0x50
    p[0..0x2C] = 0（12 个 float）
ctx+0x1298 = 2
ctx+0x129C = -1
ctx+0x12F4 = 0.0f
+ 构造 VSH_FLOATUNIFORM 命令（reg 0x02B0 族）
```

- `ctx+0x1000/0x1004/0x1008` 在 `0x1138CC` 里被当作**逐通道乘数**使用：
  ```
  ambient_R = clamp( paletteA_R + int( paletteB_R × ctx[0x1000] ), 0..255 )
  ambient_G = clamp( paletteA_G + int( paletteB_G × ctx[0x1004] ), 0..255 )
  ambient_B = clamp( paletteA_B + int( paletteB_B × ctx[0x1008] ), 0..255 )
  ```
  ⇒ 这两套调色板 + 3 个乘数就是"环境光随场景/时间变化"的机制。
- 其后循环（0x113A00 起）把 r6 对象里 `0x164+` 的启用标志、LUTINPUT 位图填进 context，
  再把 6 组调色板写进 **Light0**；`r6+0x254` 的 12 个 float 经 `0x120838`（1.0f 归一化）写进
  光照坐标系。

### 7.2 AddLight API：`0x109508`（slot 0xD0）—— 逐条解出

```
r1 = 参数块（param）
ctx = 0x9BA094；base = ctx + 0xFF8
if (base[0] >= 8) return;                       ← 最多 8 盏灯
count = base[0]
base[0x18 + (count>>5)*4] |= 1 << (count & 31)  ← ctx+0x1010 的启用位图
light = base + count*0x50                        ← 灯结构 0x50 字节
light[0x20] = param[0x10]     ┐
light[0x30] = param[0x14]     ├ 经 0x115D90 写入（3 个参数 word）
light[0x40] = param[0x18]     ┘
light[0x50] = 归一化( param[+4..+0x10] 的 4 个 float )  ← VFP：×1.0 后 VSTM
base[0] = count + 1
ctx[0xC] |= 0x2                                 ← "灯光脏"标记
```

⇒ 灯的字段：`+0x10/+0x14/+0x18` 是 3 个 word（大概率是打包颜色/参数），
`+4..+0x10` 是 4 个 float 的向量（方向/位置？），`+0x20/+0x30/+0x40/+0x50` 是派生值。
再结合 `docs/03 §6` 的 8×0x50 灯环境结构，说明 **场景灯光 = 8 个 light entry**。
